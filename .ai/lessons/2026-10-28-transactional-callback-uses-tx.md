# Callback `em.transactional` zapisuje przez `tx`, nie przez wstrzyknięty `em`

- **Problem:** `UserService.changePassword` i `register` wołały `this.#em.transactional(async () => { this.#em.nativeUpdate(...) ... })`. W MikroORM 7 `fork()` ustawia `useContext = false`, więc `em` z `withRequestScope` nie dołącza do transakcji: zapisy przez niego zatwierdzały się od razu. Gdy drugi krok rzucił wyjątek, hasło było już zmienione (a w `register` zostawało konto bez sesji). Testy z mockiem `transactional(work => work())` tego nie wykrywały; błąd znalazło code review, odtworzony na PostgreSQL.
- **Reguła:** w callbacku `em.transactional(async (tx) => …)` wszystkie zapisy idą przez `tx`. Metody serwisów wywoływane z transakcji (`SessionService.create/revokeOthers`, `InvalidateResetTokens`) przyjmują `em` jako argument (domyślnie wstrzyknięty). Mock `transactional` w testach jednostkowych przekazuje `tx` różny od zewnętrznego `em` i sprawdza, że zapisy idą przez `tx`. Rollback sprawdzaj na prawdziwym PostgreSQL (`tests/integration/transactions.test.ts`: wymuszona awaria drugiego kroku).
