# `.env.local` z roota monorepo nie był czytany przez `next dev`

- **Problem:** po rejestracji nie powstawał plik skrzynki (`EMAIL_TRANSPORT=file` w `.env.local`), a ciasteczko sesji w dev miało `__Host-…; Secure` mimo `SESSION_COOKIE_SECURE=false`. Rejestracja zwracała `201`, a log pokazywał tylko „Verification e-mail not sent”.
- **Przyczyna:** `next dev` wywołuje `loadEnvConfig` dla katalogu aplikacji (`packages/app`) i `@next/env` zwraca ten wynik z cache dla każdego następnego wywołania, jeśli nie podać `forceReload`. `loadEnvConfig(root, dev)` w `next.config.ts` niczego więc nie ładowało: zmienne z roota (`EMAIL_*`, `SESSION_COOKIE_SECURE`, `APP_ORIGIN`, …) były w dev puste (potwierdzone logiem `process.env` w `readServerConfig`). `DATABASE_URL` działał tylko dzięki wartości domyślnej w pakiecie `db`. Testy jednostkowe mockowały `@next/env`, więc tego nie widziały; build produkcyjny i testy integracyjne dostają zmienne z prawdziwego środowiska.
- **Naprawa:** `loadEnvConfig(root, dev, console, true)` (czwarty argument = `forceReload`) oraz test z prawdziwym `@next/env` (`packages/app/next-env-cache.test.ts`), który dokumentuje cache.
- **Reguła:** zmienną z `.env.local` sprawdzaj w działającym procesie (np. tymczasowy log `process.env.X`), nie tylko w pliku; testując ładowanie konfiguracji, nie mockuj biblioteki, której zachowanie (cache) jest przedmiotem błędu. Zmiana `next.config.ts` restartuje `next dev` automatycznie.
