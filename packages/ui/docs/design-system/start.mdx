# Start: jak zbudować ekran

## Charakter produktu

Gomoku to gra planszowa dla dwóch osób online: ciemna strona, drewniana plansza, jeden pomarańczowy akcent i tekst, który mówi wprost. Wszystko jest oszczędne i czytelne, a o stanie gry gracz dowiaduje się ze słów, ikon i kształtu, nie z samego koloru. Wygląd wynika z decyzji właściciela zapisanych w referencjach (R01–R02) i antyreferencjach (A01–A06), a nie z domyślnych ustawień biblioteki.

**Charakter:** oszczędny, czytelny, ciepły (drewniany), spokojny, rzeczowy.
**Antycharakter:** pstrokaty, niskokontrastowy, retro-pikselowy, techniczny (dokumentacyjny), generyczny.

## Pięć kroków budowy ekranu

1. **Znajdź wzorzec.** Czy to formularz, lista, widok szczegółów, potwierdzenie usunięcia, zaproszenie, ekran zależny od uprawnień? Wzorce: [Formularz](?path=/docs/wzorce-formularz--docs), [Lista](?path=/docs/wzorce-lista--docs), [Widok szczegółów](?path=/docs/wzorce-widok-szczegółów--docs), [Potwierdzenie usunięcia](?path=/docs/wzorce-potwierdzenie-usunięcia--docs), [Zaproszenie przez link lub kod](?path=/docs/wzorce-zaproszenie-przez-link-lub-kod--docs), [Stan zależny od uprawnień](?path=/docs/wzorce-stan-zależny-od-uprawnień--docs). Ekran epiku może już istnieć: sprawdź strony epików ([Konta](?path=/docs/design-system-konta--docs), [Partia z zaproszenia](?path=/docs/design-system-partia-z-zaproszenia--docs), [Otwarte lobby](?path=/docs/design-system-otwarte-lobby--docs), [Historia partii](?path=/docs/design-system-historia-partii--docs)).
2. **Wybierz komponenty** według [Jak wybrać komponent](?path=/docs/design-system-jak-wybrać-komponent--docs). Jeśli komponentu nie ma, zajrzyj do [Czego brakuje](?path=/docs/design-system-czego-brakuje--docs), zanim cokolwiek dorobisz.
3. **Użyj tokenów znaczeniowych** (`bg-surface-page`, `text-text-muted`, `bg-action-primary-bg`, `gap-stack`), nigdy kolorów ani odstępów z palety. Lista: [Kolor](?path=/docs/fundamenty-kolor--docs), [Odstępy i układ](?path=/docs/fundamenty-odstępy-i-układ--docs), [Typografia](?path=/docs/fundamenty-typografia--docs).
4. **Zaprojektuj stany danych:** ładowanie ([Szkielet](?path=/docs/prymitywy-szkielet-ładowania--docs)), pusto ([Pusty stan](?path=/docs/prymitywy-pusty-stan--docs)), błąd ([Stan błędu](?path=/docs/prymitywy-stan-błędu--docs)), dane częściowe, dużo danych, długie teksty, szerokość 320 px i oba motywy.
5. **Sprawdź [Czego unikać](?path=/docs/design-system-czego-unikać--docs)**, uruchom `npm run check:tokens -w @gomoku/ui` i `npm run test:stories -w @gomoku/ui`.
