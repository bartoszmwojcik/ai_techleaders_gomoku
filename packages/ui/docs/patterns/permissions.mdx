# Stan zależny od uprawnień

Wzorzec dla ekranów, które wyglądają inaczej dla niezalogowanego, gracza z niepotwierdzonym e-mailem (bez blokad), gracza z potwierdzonym e-mailem i gościa (BR-22, BR-26, D-23).

<Canvas of={Stories.EmailNiepotwierdzonyBanerNieblokujacy} />

## Kiedy używać

- Każdy ekran z akcjami zależnymi od konta: strona główna, lobby, zaproszenie, partia.

## Zasady

1. **Akcja niedostępna jest zablokowana z powodem obok**, nie ukryta bez śladu. Od 2026-10-26 niepotwierdzony e-mail niczego nie blokuje (BR-26), więc zasada dotyczy innych powodów (np. „Masz już partię”, BR-13). Źródło: prompt systemu.
2. **Przy niepotwierdzonym e-mailu zamykalny baner tłumaczy powód** ([Baner potwierdzenia e-maila](?path=/docs/produkt-konta-baner-potwierdzenia-e-maila--docs)); gra jest dostępna od razu. Zalogowany nie gra jako gość. Źródło: BR-26.
3. **Niezalogowany widzi jedną główną akcję** („Załóż konto”) i drogę do logowania w nagłówku (R02.1).
4. **Gość nie widzi lobby ani historii** i ma trwałe ostrzeżenie przy partii. Źródło: BR-22.
5. **Serwer jest strażnikiem:** interfejs tylko wyjaśnia; każda zablokowana akcja jest też odrzucana po stronie serwera.
