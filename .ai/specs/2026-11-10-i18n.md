## 📝 TLDR

Dziś każdy tekst interfejsu jest po polsku i wpisany na stałe: ok. 100 plików w `packages/app/src` i 29 w `packages/core/src` zawiera polskie litery w kodzie niebędącym testem (zmierzone `grep`-em; do tego komunikaty serwera, opisy narzędzi MCP i szablony e-maili). Za ok. 14 dni właściciel robi pokaz (E14) dla Francuzów, którzy **oglądają jego ekran**; chce interfejs po angielsku i francusku, a po niemiecku, jeśli niedrogo. **Po wdrożeniu (zachowanie przyszłe)** aplikacja ma własny, mały, typowany słownik (bez nowej zależności): język wybiera `?lang=` w adresie (mały `proxy.ts` zapisuje ciasteczko `gomoku_lang` z samym kodem języka i usuwa parametr z adresu), zapasowo `Accept-Language`, domyślnie polski, bez prefiksu `/fr/`. Serwer rozwiązuje język i teksty, a komponenty klienckie dostają gotowe napisy przez propsy (domyślnie polskie, więc **testy polskie przechodzą bez zmian asercji**). Praca idzie w trzech niezależnych fazach epiku E15: **A** fundament (jedna historyjka, przed E14-S01), **B** widok pokazu i formularz administratora na kluczach PL/EN/FR (razem z E14), **C** reszta ekranów paczkami z maszynowym kryterium „brak polskich literałów w tej grupie”. Komunikaty błędów API tłumaczy się **na krawędzi po `AppError.code`**; `message` zostaje polskim zapasem i kontraktem, a `core` nie dostaje pojęcia języka. Komunikaty MCP i e-maile są poza etapami A i B.

## 📝 API: moduł i słownik

### Publiczne API (typy, krótko)

```ts
// @gomoku/core/i18n/translator
type Plural = { one?: string; few?: string; many?: string; other: string };
type Message = string | Plural;
type Dict = { readonly [key: string]: Message | Dict };           // jedna przestrzeń
type Translator = {
  (key: string, params?: Record<string, string | number>): string; // klucz kropkowy: "session.logout"
  number(n: number, options?: Intl.NumberFormatOptions): string;
  megabytes(n: number): string;                                     // pl/en/de "16 MB", fr "16 Mo"
  locale: Locale;
};
createTranslator(locale: Locale, dict: Dict): Translator
```

Typowanie kluczy: katalog PL jest `as const`-podobnym obiektem; `type Keys<N> = DottedKeys<typeof pl[N]>` daje autouzupełnianie, a `t` w komponencie jest zawężony do `Keys<N>` przez `createTranslator<typeof pl.header>(…)` (generyk wyprowadzony z propsa `dict`). Tłumaczenia EN/FR deklarowane jako `const en: Catalog<typeof pl.header> = {…}` (mapowany typ wymusza te same klucze), DE jako `DeepPartial<Catalog<…>>`.

### Interpolacja i liczba mnoga

`"Czat ({count} nowych)"`-owe sklejanie zastępuje wpis `chat.unread: { one: "{count} nowa", few: "{count} nowe", many: "{count} nowych", other: "{count} nowej" }` (PL) i `{ one: "{count} new", other: "{count} new" }` (EN). Brak wymaganej formy → `other`. Parametr w tekście bez wartości → **błąd w testach i dosłowny `{name}` w produkcji** (jeden test w translatorze pilnuje obu).

### Ładowanie katalogów bez rozdymania bundla

`catalogs/index.ts` zawiera tylko mapę `() => import("./fr/show")` itp. Moduł jest `server-only`; klient dostaje wyłącznie wynik `loadNamespace` jako serializowalny props. Jeden request ładuje tylko przestrzenie potrzebne stronie (`header` zawsze, plus przestrzeń strony). Polskie wartości domyślne propsów komponentów klienckich importują katalog PL danej przestrzeni — **ten sam tekst jest dziś w bundlu jako literał**, więc rozmiar się nie zmienia, a EN/FR/DE nigdy nie trafiają do bundla klienta (kryterium pomiaru I19).

## 📝 Language resolution and cookie

**Kolejność:** (1) ciasteczko `gomoku_lang` z poprawnym kodem (`isLocale`); (2) `Accept-Language` (I6); (3) `pl`. `?lang=` nie jest źródłem dla renderu — `proxy` zamienia go na ciasteczko i usuwa z adresu, więc render widzi tylko ciasteczko.

**Ciasteczko (I4):** `gomoku_lang=<pl|en|fr|de>; Path=/; Max-Age=31536000; SameSite=Lax; HttpOnly; Secure` (Secure poza lokalnym HTTP, tak jak `themeCookie`: warunek z `request.nextUrl.protocol`). Przechowuje wyłącznie kod języka. Odrzucenie zmanipulowanej wartości: `isLocale` jest ścisłe (dokładne kody, bez regionów), nieznana wartość = ciasteczko ignorowane (jak `parseTheme`, `core/theme/theme.ts:11-13`).

**Proxy (I5):**

```ts
export const config = { matcher: [{ source: "/((?!api|_next|backend|.*\\..*).*)", has: [{ type: "query", key: "lang" }] }] };
export function proxy(request: NextRequest) {
  const url = request.nextUrl.clone();
  const lang = url.searchParams.get("lang");
  url.searchParams.delete("lang");
  const response = NextResponse.redirect(url, 307);
  if (isLocale(lang)) response.cookies.set(LANG_COOKIE, lang, langCookieAttributes({ secure: url.protocol === "https:" }));
  return response;
}
```

Zachowanie: `?lang=fr&projektor=1` → ciasteczko `fr`, 307 na `?projektor=1`; `?lang=xx` → 307 bez ciasteczka; wielokrotny `lang` → bierze się pierwszy, wszystkie są usuwane. Strona `/backend` i `/api/*` nie przechodzą przez `proxy`. Dla żądań bez `lang` `proxy` **nie działa** (matcher `has`), więc zerowy koszt na pozostałych żądaniach.

**Layout:**

```tsx
const locale = await getLocale();
<html lang={locale} data-theme={theme ?? undefined} suppressHydrationWarning>
```

`getLocale()` czyta `(await cookies()).get(LANG_COOKIE)?.value` i `(await headers()).get("accept-language")`. Layout czyta `cookies()` już dla motywu (`layout.tsx:25`), więc **nie powstaje nowa dynamiczność**. Test layoutu (`layout.test.tsx:7-16`) mockuje `next/headers` tylko z `cookies`; fundament dopisuje do mocka `headers: async () => new Headers()` (zmiana osprzętu testu, asercje bez zmian — jedyna edycja istniejącego testu w fazie A, zob. I8).

## 📝 API errors at the edge

**Zasada:** kontrakt wsteczny — `message` pozostaje polskim ciągiem w kopercie, `core` nie zna języka. **Tabela kodów:** przestrzeń `errors` (`errors.api.<CODE>`: tytuł, szczegóły, ewentualnie `{minutes}`), budowana w paczce C5 z **kodów faktycznie używanych**: skaner testowy zbiera literały kodów z `code: "…"` i konstruktorów `AppError`/`*Error` w `core/src` i `server/` i wymaga wpisu w tabeli **albo** wpisu na liście „nie dla użytkownika” (np. `PAYLOAD_TOO_LARGE`, `CSRF`) — to maszynowe kryterium paczki.

- **Kod z wpisem:** UI pokazuje tekst katalogu (z parametrami z `error.data`, np. `reason` botów, `retryAfterSeconds`).
- **Kod bez wpisu:** zapas = polskie `message` z koperty (nie tłumaczone; widoczne w teście jako brak wpisu do uzupełnienia).
- **`fieldErrors`:** w fazach A i B nie dotyczą (widok pokazu ich nie wyświetla; `/show` używa kodów `SHOW_RUNNING`, `BOT_UNAVAILABLE`, `VALIDATION`). W C5 spike (I13): kod w `issue.params` + pole opcjonalne `fieldIssues`; do czasu wdrożenia komunikaty walidatorów zostają polskie w obcych językach i **nie wchodzą do kryterium „brak polskich literałów” dla tych formularzy** (wyjątek zapisany jawnie na liście `i18n-allowlist.ts` z powodem).
- **Co zostaje polskie na stałe:** `AppError.message` w kopercie, komunikaty MCP (I20), logi i `describeError` (nie zawierają `message`, `describe-error.ts`), e-maile (do decyzji o `locale`).
- **`BOT_UNAVAILABLE_MESSAGE`:** stała w `core` zostaje (kontrakt `503`); klient pokazuje tekst katalogu po kodzie `BOT_UNAVAILABLE`, a `lib/games/opponent.ts:23` (`BOT_UNAVAILABLE_TEXT`) staje się polskim zapasem.

## 📝 Edge Cases & Failure Scenarios

| Sytuacja | Zachowanie |
|---|---|
| Zmanipulowane ciasteczko (`gomoku_lang=../../x`, `PL`, puste) | `isLocale` ścisłe → ignorowane, następne źródło; nie trafia do HTML |
| `?lang=fr` na `/backend`, `/api/*` | Poza matcherem proxy: parametr ignorowany, panel po polsku, API bez zmian |
| `?lang=de` | Ciasteczko `de`, render z zapasem EN→PL; przełącznik niemiecki ukryty (I7) |
| Brak klucza w FR | Zapas EN→PL (I9), `console.warn` w dev, test parzystości w CI blokuje dla EN/FR |
| `Accept-Language: *` lub `zh-CN` | Brak obsługiwanego → `pl` |
| Bardzo długi lub zdeformowany `Accept-Language` | Ucięty do 256 znaków i 20 pozycji, błędne `q` odrzucone |
| Boty/crawlery bez nagłówków | `pl` |
| Zapisana strona/zakładka z `?lang=fr` | Adres zostaje czysty; link z `?lang=fr` ustawia ponownie cookie |
| Przełączenie języka w trakcie partii | Pełne przeładowanie; stan gry odczytywany od nowa; polling klienta restartuje się (tak jak po każdym przeładowaniu); zegar liczony względem `clock.now` serwera (bez zmiany) |
| Niezgodność hydracji (ciasteczko vs. nagłówek) | Wykluczona z założenia: jeden `getLocale()` na żądanie (React `cache`), klient nie czyta `navigator`; `Intl` w kliencie używa `locale` z propsa |
| Przeglądarka bez ciasteczek | Każde żądanie `Accept-Language`/`pl`; przełącznik działa jednorazowo (307, brak trwałości) — do odnotowania w dokumentacji |
| Pokaz na obcym komputerze z inną przeglądarką | Link `…/show/<id>?lang=fr` ustawia język niezależnie od przeglądarki (I5) |
| Cache współdzielony przed aplikacją | `Vary: Cookie, Accept-Language` na dokumentach `(frontend)` (I21), sprawdzić `curl`-em |
| Tekst dłuższy niż miejsce (FR/DE) | I16: obcinanie nazw, brak stałych szerokości, przegląd 320 px |
| Klucz z parametrem bez wartości | Błąd w teście; w produkcji dosłowne `{name}` |

## 📝 Risks & Impact Review

- **Konwencja wiążąca (`AGENTS.md:56`)** — zmiana obejmuje wszystkich agentów i wymaga zatwierdzenia treści (I23). Skutek uboczny dobry: nowy kod nie dodaje literałów do zmigrowanych grup (test I11).
