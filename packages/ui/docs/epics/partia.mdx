# Epik E02: Partia z zaproszenia

Utworzenie partii i zaproszenie, dołączenie, ruchy i wygrana, zegary, powrót po rozłączeniu. Źródła: `.ai/specs/product-brief.md` (BR-04…BR-07, BR-09…BR-11, BR-22), `.ai/specs/implemented/2026-10-24-game-invitations.md`, `.ai/specs/implemented/2026-10-25-game-moves-win-detection.md`, zgłoszenia #23 i #24.

## Przepływ

1. Zalogowany gracz z potwierdzonym e-mailem tworzy partię i dostaje link oraz kod (`/games/{id}`, status „czeka”).
2. Zaproszony otwiera link (`/invite/{kod}`) albo wpisuje kod (`/join`) i dołącza jako zalogowany albo jako gość.
3. Gracze wykonują naprzemienne ruchy; każdy ma zegar 10 minut (czas liczy serwer).
4. Partia kończy się pięcioma w linii, remisem albo końcem czasu; po powrocie z rozłączenia gracz widzi stan z serwera.

## Przeciwnik „Agent” (E06-S01, BR-31)

Agent dołącza do partii prywatnej przez MCP, nie przez przeglądarkę. Człowiek widzi go jako **„Agent”** (zwykły tekst, bez „(gość)”, bez ikony); gdy agent podał nazwę modelu, widzi **„Agent · {nazwa} (deklarowane)”**. Oznaczenie „(deklarowane)” jest obowiązkowe: nazwa jest niezweryfikowana. Nazwa jest węzłem tekstowym (bez HTML, Markdownu i linków), przy 320 px skracana wielokropkiem, a „Agent” i „(deklarowane)” nigdy się nie skracają. Rewanżu z agentem nie ma: panel pokazuje tylko podpowiedź. Opakowanie `AgentName` w `docs/screens/game-screen.tsx` odpowiada `PlayerLabel` aplikacji; luka #135 (skracanie nicku gościa) go nie dotyczy.
